# 面试展示截图清单

仅以下 10 张；这是待截图清单，不代表截图或视觉验收已完成。遮挡个人身份、敏感来源和凭据。Langfuse 只截已有 r3，不运行实验。评论展示需有授权。

## 1. Overview

- 截什么：规模、关键发现与 AI 质量快照。
- 讲什么：产品分析与可信度验证放在同一工作台。
- 证明什么：信息架构和完整链路。

## 2. Feedback Analysis

- 截什么：L002 原文、结构化标签及关联 Issue。
- 讲什么：模型判断回到原文，不是孤立摘要。
- 证明什么：可解释性与可追溯性。

## 3. Issue → Evidence

- 截什么：Top 1 五个 ID 与全部原文展开。
- 讲什么：可以检查所有成员，不止代表评论。
- 证明什么：证据链与归并边界。

## 4. Evaluation Lab：V1 → V3

- 截什么：历史本地 Dev 三版对比。
- 讲什么：先统一 taxonomy 再修边界，不把输出空间变化说成纯能力提升。
- 证明什么：实验口径与迭代方法。

## 5. Holdout Metrics

- 截什么：Accuracy/Macro-F1 与 All-fields 37/62。
- 讲什么：单字段高分不等于整条可免复核。
- 证明什么：泛化与指标理解。

## 6. Error Analysis

- 截什么：高→中等错误模式及原始错误样本。
- 讲什么：严重程度弱、低类未覆盖，未据此创建 V4。
- 证明什么：识别限制而非选择性报喜。

## 7. Langfuse r3 Experiment

- 截什么：三个 final-r3 对比及一条 Generation/Scores，可用一张拼图。
- 讲什么：60 次重新生成、294 Scores，与历史结果分开。
- 证明什么：实验管理与可观察性。

## 8. Product Insights

- 截什么：两产品模块分布，保留样本数。
- 讲什么：31/32 条问题反馈的样本画像，不是市场质量排名。
- 证明什么：竞品分析及样本边界。

## 9. Top 1 产品卡

- 截什么：通知 Issue、五个 ID、优先级、建议及未来指标。
- 讲什么：重复证据和核心场景支持排序，但方案不是原始事实。
- 证明什么：从数据到产品决策。

## 10. Mini PRD / 原型规格

- 截什么：现有 PRD 流程与三帧 Markdown 规格，可同图拼接。
- 讲什么：入口→诊断→验证，未知与未恢复有兜底。
- 证明什么：需求边界与交互闭环。
