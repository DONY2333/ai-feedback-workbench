# 项目案例：从用户评论到可验证的产品需求

## 1. 为什么做

产品团队面对分散评论，既要区分有效问题与情绪，也要把不同措辞归为可讨论的需求。直接生成摘要很快，却难以追溯原文、判断遗漏和误判。我用本地工作台验证这条流程，不声称已经解决真实企业的全部反馈管理问题。

## 2. 我定义的产品目标

目标是「用户反馈 → 可验证的问题洞察 → 产品需求」。每个问题能回到原始 ID，每个成绩有人工 Gold 和分母，设计建议不能冒充事实。预期使用者是产品经理与运营，没有已验证的活跃用户规模或画像。

## 3. MVP

Python/pandas 读取清洗 Excel，独立模型客户端通过 OpenAI-compatible API 输出八字段 JSON，再用 Streamlit 展示。字段包括有效性、类型、模块、场景、痛点、情绪、严重程度和原始证据。Mock 用于联调，正式 Evaluation 禁止 fallback。

最终四页为 Overview、Feedback Analysis、Evaluation Lab、Product Insights。默认读保存结果，不自动调用模型；可以从反馈看 Issue，再看全部原始证据。缺失数据有提示，Windows DLL 导入失败可用转义 HTML 展示表格。

## 4. 最大问题：AI 输出可信吗？

JSON 格式正确不等于业务判断正确。最初自由文本模块无法与人工标签稳定比较，Bug 和使用困难也容易混淆。因此先建立本地逐字段比较、错误样本和版本结果，再考虑平台化。当前分类指标只覆盖有效性、类型、模块和严重程度，场景、情绪及证据质量仍需另行验证。

## 5. Gold Set & Taxonomy

使用已有 Excel 中 82 条人工 Gold，保留列映射与 ID，不让模型标签反向修正 Gold。正式类型为 Bug、功能建议、使用困难、正向评价、情绪/无效反馈；V2 起模块固定 19 类，严重程度为高、中、低、不适用。

自动评价有效性、类型、模块、严重程度。核心痛点为自由文本，只保存对照，不做字符串准确率。Gold 严重程度不适用则跳过，整条正确需所有适用字段匹配。没有记录完整独立多标注者裁决或一致性测量，人工标签也存在不确定性。

## 6. Prompt V1 → V3：根据错误修改

| 历史本地 Dev | Valid | Type | Module | Severity |
| --- | ---: | ---: | ---: | ---: |
| V1 | 19/20 = 95% | 18/20 = 90% | 1/20 = 5% | 12/18 = 66.67% |
| V2 | 19/20 = 95% | 16/20 = 80% | 18/20 = 90% | 12/18 = 66.67% |
| V3 | 20/20 = 100% | 19/20 = 95% | 18/20 = 90% | 14/18 = 77.78% |

V1 后发现 taxonomy 不一致、类型边界、有效性和严重程度标准不清。V2 先统一输出契约：固定模块，统一类型拼写和严重程度，明确正向与无效反馈严重程度不适用。模块提升包含输出空间变化，不能说纯模型能力提高 85 个百分点；类型反而从 90% 降至 80%。

V2 后发现 Bug 过宽、遗漏后文撤销、具体短文本或混合语言被判无效、模块映射不足。V3 只补这些规则，并按实际任务影响判断严重程度，不因情绪自动升级。没有针对 ID 写死答案，也没有消融实验证明每条规则的独立收益。

## 7. 防止 Evaluation Overfitting

Dev 为 L001–L020，共 20 条；Holdout 为 L021–L043 + W001–W039，共 62 条。前者迭代，后者在 V3 冻结后首次正式测试，按 ID 校验避免漏样本和重复。Dev 全为飞书，分布不均衡。

反复看错误再调规则可能拟合样本，而非未来反馈。Holdout 已被分析，不能再证明后续版本的完全未见泛化。项目停在 V3，未根据 Holdout 创建 V4。

## 8. 最终泛化结果

| V3 Holdout | 正确/适用数 | Accuracy | Macro-F1 | Weighted-F1 |
| --- | ---: | ---: | ---: | ---: |
| Valid | 61/62 | 98.39% | 97.49% | 98.36% |
| Feedback Type | 54/62 | 87.10% | 85.68% | 86.45% |
| Product Module | 50/62 | 80.65% | 55.39% | 81.35% |
| Severity | 31/44 | 70.45% | 47.10% | 73.83% |

整条完全正确为 37/62 = 59.68%，单字段准确率不等于无需复核。模块 Macro-F1 按固定 19 类计算，5 类未覆盖按零参与，因此既有长尾问题，也有覆盖影响。严重程度高 31、中 13、低 0；始终猜高同样为 70.45%，不能包装成可靠能力。

主要错误：高→中 11、使用困难→Bug 5、安装/更新→性能/稳定性 3。同一评论可贡献多个字段错误。证据见[实验总结](../evaluation/results/experiment_summary.md)。

## 9. 用 Langfuse 管理版本实验

本地 Evaluation 解决方法和口径，Langfuse 解决实验管理与可观察性。Trace/Generation 记录调用，Score 记录 Gold 比较，Dataset 固定 Dev，Experiment 区分版本。

先用 L001 验证历史 Prompt/Schema，随后发现当前 normalizer 将 V1 自由模块映射成「其他」造成假正确。之后隔离 raw_output、normalized_output、score_input，V1 自由文本保留 Exact Match。历史三版 summary 回放一致，但缺完整旧源码和原始响应，均标 partial reproduction。

正式 r3 三版各重新生成 20 条：60 次请求、60 成功、294 Scores、0 失败、0 retry。V1/V2/V3 All-fields 为 0%/60%/70%；V3 Valid 100%、Type 95%、Module 90%、Severity 72.22%。它不是历史 Dev 或 Holdout，小幅差异可能来自重新生成非完全确定性。

总 token 135,738，平均 API latency 8.774s；三版总 token 为 22,773 / 52,024 / 60,941。质量改善伴随长度与用量增加，无可信固定价格便不算货币成本。

## 10. 工程问题

401 是系统性鉴权故障，继续只会重复失败，因此 fail-fast。早期 20 秒 timeout 中止整批，后改为区分临时故障：timeout、429、5xx 最多显式重试一次，两次失败记录该项并继续；鉴权、配置、代码或 Schema 错误仍停止。

r3 timeout 45 秒、SDK max_retries=0，每项最多两次，记录 attempt、原因与用量。实际 60/60 成功且未触发 retry，不能因此承诺所有生产异常已验证；异常分支由离线测试覆盖。

## 11. 从模型输出走到产品决策

复用历史 V3 Dev + Holdout，不混 r3，不用 Gold 修正：82 条 → 63 条问题反馈 → 产品与预测模块粗分 24 组 → 54 候选 Issue → Top 5 与竞品画像。

归并使用保守离线规则：同产品同模块内按问题锚点及足够长的相同痛点归并，建议单独分流，不确定保留单条。54 个中仅 4 个多成员，存在碎片化。后续重点核对 Top 5 等候选，尚未全面深度人工复核。Top 5 的方案与排序作为固定编辑内容保存在脚本中；新批次仅生成独立候选，不套用这些结论。

在当前样本中，飞书 31 条问题反馈里通知 6、账号 5、会议 4；企业微信 32 条里账号及性能/稳定性各 7、安装/更新 6。Top 5 是通知未送达/展示异常（5 条）、验证码未送达（2）、附加资源下载失败（3）、语言切换不生效（3）、换机验证循环（1）。依据重复、预测严重程度与核心场景排序，不编商业分值。

两个产品均有通知与账号问题，但非市场代表样本，不能判整体优劣。[正式产品洞察](../analysis/results/e2_product_insights/product_insights.md)保留全部卡片与限定语。

## 12. Top 1 Requirement

ISS-3955d4f6ed9d 的证据为 L002、L003、L010、L016、L038，共五条；预测高 4、中 1。评论确认通知不来、消失或通知栏缺失，部分用户调过后台配置仍失败，不能直接推断全是权限问题。

Notification Health Check 是产品方案建议：检查可读取状态 → 修复引导 → 测试 → 用户确认或提交。未知不能写成关闭，本地正常不等于推送正常，请求受理不等于收到。需客户端/服务端可行性和用户验证。

已完成 [Mini PRD](top1_notification_mini_prd.md) 与 [3 Frame 页面规格](top1_notification_figma_spec.md)：入口、诊断、验证。没有实际 Figma 文件，没有实现通知功能。

## 13. 项目结果

完成四页可运行工作台、双向证据链、82 条 Gold 评价闭环、历史版本实验与 Langfuse 记录、离线归并、竞品样本画像、Top 5、Mini PRD 与原型规格。价值在于将 AI 结果转成有边界的产品判断，未上线，无已证实业务收益。

## 14. 如果继续做（仅可能方向）

优先补充更多来源的真实反馈与独立测试集，验证严重程度和长尾模块；对问题归并做人工抽检，再判断是否需要语义聚类。通知诊断方案仍需用户访谈和技术评审。
